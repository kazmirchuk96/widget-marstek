# widget-marstek

Віджет iPhone для зарядної станції Marstek Venus E: відсоток заряду, поточне навантаження, на скільки годин вистачить заряду. Працює в застосунку Scriptable (JavaScript), не нативний застосунок.

## Файли

- `Marstek.js` — увесь віджет одним файлом. Завантажувач виконує його як є, тому він має лишатися самодостатнім: без імпортів, без збірки.
- `Marstek.js.sig` — підпис `Marstek.js` (HMAC-SHA256). Створюється автоматично перед комітом, руками не редагувати.
- `Loader.js` — завантажувач, який стоїть на iPhone: бере `Marstek.js` з GitHub, перевіряє підпис, запускає.
- `deploy.sh` — тести, підпис і заливка на GitHub.
- `.signing-key` — код підпису (16 символів). У `.gitignore`, у репозиторій не потрапляє. Не показуй його ніде, крім чату з користувачем.
- `test/test.js` — тести для Node.
- `README.md` — інструкція для користувача.

## Перевірка

```bash
node test/test.js
```

Тест перевіряє чисту логіку (MD5, розрахунок, оцінку на змодельованих розрядах, підписи у віджеті) і проганяє `Marstek.js` та `Loader.js` на заглушках Scriptable: усі розміри віджета, роботу без мережі, меню, вхід, налаштування, підпис і відкат оновлень. Запускай після кожної зміни. Справжній Scriptable і хмару Marstek звідси перевірити неможливо — кажи про це прямо.

## Заливка на iPhone

Користувач не розробник і файли вручну не переносить. iCloud Drive у нього заповнений, тому доставка йде через GitHub:

- Публічний репозиторій `kazmirchuk96/widget-marstek`. На iPhone у Scriptable один раз вставлено `Loader.js`.
- Завантажувач раз на 30 хвилин (а при запуску в Scriptable — щоразу) качає `Marstek.js.sig`; якщо підпис новий, качає `Marstek.js`, перевіряє HMAC ключем із Keychain (`marstek.signkey`) і запускає. Версія стає основною лише після запуску без винятку; якщо вона падає, запускається попередня, а зламаний підпис запам'ятовується (`rejected` у `marstek-loader.json`) і більше не пробується.
- Хуки git (не зберігаються в репозиторії, після клонування створи заново, `chmod +x`):
  - `.git/hooks/pre-commit` → `exec ./deploy.sh prepare` — тести, потім підпис і `git add Marstek.js.sig`; якщо тести падають, коміт скасовується;
  - `.git/hooks/post-commit` → `exec ./deploy.sh push` — `git push origin main`.
- Після коміту перевір у виводі рядок `deploy:` і скажи користувачу, чи залито. GitHub кешує raw-файли до ~5 хвилин; якщо `.sig` і `.js` оновилися не одночасно, завантажувач просто спробує пізніше.
- Якщо змінити `Marstek.js` без коміту через хук (або закомітити з `--no-verify`), підпис не збіжиться і телефон тихо лишиться на старій версії.
- Репозиторій публічний: жодних особистих даних у файлах і комітах (email автора в цьому репозиторії — noreply від GitHub).
- Якщо змінюєш `Loader.js`, користувачу доведеться вставити його в Scriptable заново — уникай цього без потреби.
- Помилка, яка не кидає виняток (наприклад, кривий вигляд), відкатом не ловиться. Не використовуй API Scriptable, у яких не впевнений.

## Як влаштовано

- Дані — з неофіційного хмарного API Marstek (`eu.hamedata.com`): вхід `v2_get_device.php` (email + md5 пароля) дає токен, `getDeviceList` повертає станції з полями `soc`, `load`, `charge`, `discharge`, `report_time`. Джерело знань про API — інтеграція `DoctaShizzle/marstek_cloud` для Home Assistant.
- Хмара НЕ передає потужність виходу Backup (режим UPS): `load`, `discharge`, `grid` дорівнюють 0, навіть коли станція розряджається (перевірено на Venus E 3.0, прошивка 148). Чи передає вона потужність заряджання — не перевірено.
- Тому навантаження оцінюється за швидкістю зміни заряду. `updateHistory` зберігає в `marstek-history.json` моменти зміни відсотка: `t` (середина між замірами) і `err` (половина паузи). `estimateFromHistory` бере найкоротше свіже вікно з похибкою часу до 20% і повертає швидкість із довірою `ok`/`low`, або `collecting` (даних замало), або `idle` з верхньою межею (заряд давно стоїть). Якщо хмара таки дає ненульову потужність, вона має пріоритет.
- Поле `report_time` ненадійне: воно може не змінюватися пів години, хоча `soc` оновлюється. Час заміру для історії й час у заголовку віджета — це час нашого запиту.
- iOS оновлює віджет нерегулярно, тому користувач додатково запускає скрипт автоматизацією в Shortcuts (при відкритті застосунків). У такому запуску `config.runsInApp` і `config.runsInWidget` обидва false: скрипт лише отримує дані й поповнює історію.
- Натискання на віджет відкриває `scriptable:///run/Marstek?refresh=1&family=…` — попередній перегляд без меню. Звичайний запуск у Scriptable показує меню.
- Налаштування станції (ємність, резерв, назва) користувач змінює в меню; вони лежать у `marstek-settings.json` на телефоні й перекривають `CONFIG`.
- Повторний вхід у хмару — не частіше ніж раз на 10 хвилин (крім запуску в Scriptable).
- Вдома немає постійно ввімкненого комп'ютера, тому посередник для Local API не розглядаємо. Scriptable не вміє UDP, тож локальний Open API станції (порт 30000) напряму недоступний.
- Облікові дані зберігаються лише в Keychain телефона (`marstek.email`, `marstek.pwdhash`, `marstek.token`). Ніколи не вписуй email, пароль, токен чи код підпису у файли репозиторію.
- У кінці `Marstek.js` є гілка `typeof ListWidget === "undefined"`: поза Scriptable скрипт не запускає `main()`, а експортує чисті функції для тестів.
- Верхні три рядки-коментарі (`Variables used by Scriptable`) не чіпати — це метадані іконки.

## Параметри станції

Venus E 3.0: ємність 5,12 кВт·год, глибина розряду в застосунку 88%, тобто резерв (`minSoc`) 12%. Телефон користувача англійською, тексти у віджеті — українською.
