# widget-marstek

Віджет iPhone для зарядної станції Marstek Venus E: відсоток заряду, поточне навантаження, на скільки годин вистачить заряду. Працює в застосунку Scriptable (JavaScript), не нативний застосунок.

## Файли

- `Marstek.js` — увесь віджет одним файлом. Завантажувач виконує його як є, тому він має лишатися самодостатнім: без імпортів, без збірки.
- `Loader.js` — завантажувач, який стоїть на iPhone і підтягує `Marstek.js` з GitHub.
- `deploy.sh` — заливка на GitHub.
- `test/test.js` — тести для Node.
- `README.md` — інструкція зі встановлення для користувача.

## Перевірка

```bash
node test/test.js
```

Тест перевіряє MD5 проти `crypto`, розрахунок часу роботи та проганяє весь скрипт на заглушках Scriptable для малого, середнього віджета й екрана блокування. Запускай після кожної зміни `Marstek.js`. Справжній Scriptable і хмару Marstek звідси перевірити неможливо — кажи про це прямо.

## Заливка на iPhone

Користувач не розробник і файли вручну не переносить. iCloud Drive у нього заповнений, тому доставка йде через GitHub:

- Публічний репозиторій `kazmirchuk96/widget-marstek`. На iPhone у Scriptable один раз вставлено `Loader.js`; при кожному запуску він завантажує `Marstek.js` з гілки `main` (raw.githubusercontent.com), зберігає копію і виконує її. Без мережі запускає збережену копію.
- `deploy.sh` проганяє тести й робить `git push origin main`. Хук `.git/hooks/post-commit` викликає його після кожного коміту, тож коміт = заливка. Хук не зберігається в репозиторії: після клонування створи його заново (`#!/bin/sh` + `exec ./deploy.sh`, `chmod +x`).
- Після коміту перевір у виводі рядок `deploy:` і скажи користувачу, чи залито. GitHub кешує raw-файли до ~5 хвилин.
- Репозиторій публічний: жодних особистих даних у файлах і комітах (email автора в цьому репозиторії — noreply від GitHub).
- Якщо змінюєш `Loader.js`, користувачу доведеться вставити його в Scriptable заново — уникай цього без потреби. Завантажувач перевіряє, що в коді є рядок `API_DEVICES`; не перейменовуй цю константу.

## Як влаштовано

- Дані — з неофіційного хмарного API Marstek (`eu.hamedata.com`): вхід `v2_get_device.php` (email + md5 пароля) дає токен, `getDeviceList` повертає станції з полями `soc`, `load`, `charge`, `discharge`, `report_time`. Джерело знань про API — інтеграція `DoctaShizzle/marstek_cloud` для Home Assistant.
- Хмара НЕ передає потужність виходу Backup (режим UPS): `load`, `discharge`, `grid` дорівнюють 0, навіть коли станція розряджається (перевірено на Venus E 3.0, прошивка 148). Тому навантаження оцінюється за швидкістю зміни заряду: `updateHistory` зберігає моменти зміни відсотка в `marstek-history.json` на телефоні, `estimateFromHistory` рахує відсотки за годину за останні 2 години. Оцінка показується зі знаком ≈; якщо хмара таки дає ненульову потужність, вона має пріоритет. Вдома немає постійно ввімкненого комп'ютера, тому посередник для Local API не розглядаємо.
- Scriptable не вміє UDP, тому локальний Open API станції (порт 30000) напряму недоступний.
- Облікові дані зберігаються лише в Keychain телефона (`marstek.email`, `marstek.pwdhash`, `marstek.token`). Ніколи не вписуй email, пароль чи токен у файли репозиторію.
- У кінці `Marstek.js` є гілка `typeof ListWidget === "undefined"`: поза Scriptable скрипт не запускає `main()`, а експортує чисті функції для тестів.
- Верхні три рядки-коментарі (`Variables used by Scriptable`) не чіпати — це метадані іконки.

## Параметри станції

Venus E: ємність 5,12 кВт·год, резерв (`minSoc`) 12%. Час роботи = ємність × (заряд − резерв) ÷ потужність розряду; якщо батарея не розряджається — ділимо на навантаження; під час заряджання показуємо час до повного заряду.
